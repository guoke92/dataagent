# llm-wiki 维护约定

这是 wiki 的维护约定，不是数据库 schema。

## 三层记录

账本是产品库里的 `wiki_` 表，不是文件树。

- `wiki_raw` 只放该来源的提取。刷新只替换这一行。
- `wiki_claims` 只放 facts_only 写下的本源事实。记录带 source_id，不与其他来源合并。
- `wiki_pages` 只放编译后的页。`wiki_log` 追加日志。`wiki_values` 放值索引。

适配器只写自己的 raw 和 ground。编译器只写 wiki。

## 扫描

数据库扫描是同一条异步任务：保存数据源、重新扫描、单表刷新都入队 `datasource-introspect`，请求立即返回。执行器一次只跑一个扫描，按表让出事件循环。

同一列可以同时是关联的一端、拥有完整值域，并在字段概要里显示 top K。采集按四步走，不把列收成互斥角色。

1. 排除大字段（json / blob / MySQL `text` 等）和加密列。加密列在字段上标明，不写最小最大、不写实例、不进值索引、不建 sketch。
2. 时间、日期、雪花 id、自增只提取范围，扫描时更新 MinHash sketch，不保存全部取值。
3. 其余列并行提取完整值域。基数不设上限。字段概要的 top K 从全量结果截取。短 varchar 拼接串拆成值域成员。
4. 用 MinHash 估计包含系数筛候选关联，再对候选做精确校验。比较按字符串相等，包含系数限制在 0 到 1。采集记下过线测量；两个低基数非键列标 veto。父键是主键、唯一约束，或高区分度且基数够大的列。

采集和发表分开。`facts_only` 不调用模型。表、列、注释、类型、空值、范围、字段 top K、已声明外键（置信度 1）直接成页。完整取值进 `wiki_values`。值域页只保留基数和 top K。注释里能解析出至少两个「码 = 含义」的列，字典和值域成对，标签用注释原文。列注释只留在字段上，不单独发术语页。测量关联和「像枚举但注释没写含义」的值域只记主张。编译指纹含规则版本；证据未变时用已存测量按新规则重编页，不去连库重扫。

`semantic` 要求本源 ground 已存在。规则先处理明显项：路径和备注不留值域，基数超过上限的值域直接保留、不进字典。模型只看基数不超过上限的值域，一次回答留不留、是不是闭合枚举；是才补标签，不得增删码值。注释里已经带标签的字典，模型没有明确否定就保留。关联和这轮值域判断并行，每批并发不超过 4。关联在「外键 / 共享编码 / 不成立」里选，只有外键才发表。模型没返回、返回空、或调用失败，未带标签的字典和测量关联都不发表。发表集只含这次写下的页。人工页仍保留。字段叫法沿用列注释，扫描时不再逐列向模型要短描述。

## 主张域权威序

高位缺席时下一位补上，并标明级别。高位后到时改写 wiki，低位原文留在自己的 ground。

- 物理身份：数据库。
- 已声明外键：数据库。源码可以补充，不能撤掉。
- 业务术语：文档，其次对话。数据库列注释留在字段上，不单独成术语页。
- 业务逻辑与业务规则：源码，其次文档。
- 字段关联（DDL 之外）：源码直接成页。数据库测量由模型判定为外键后才成页，文档仅在写明且不冲突时。
- 枚举字典：源码解释含义。数据库记录实际取值并编译值域页。注释码值直接发字典页。其余闭合枚举由模型判定后再发字典页，与值域页同时存在。文档在源码没有字典时补充叫法。模型补 label 时不得增删码值。
- 术语到列的桥：源码。
- 问法样例：一次成功的只读 SQL 写成一条待审页，每条 SQL 单独一页。人点采纳后才是已接受，召回只用已接受的问法。它不改写术语、规则或关联。

## 召回

一次 `recall_wiki` 走完四步，不再把值域页和术语页混进同一个列表。

1. 从问话里抽出候选说法，到 `wiki_values` 对上具体值和列。对不上的说法留给 `lookup_values` 或一条探针 SQL。
2. 术语、口径、已采纳问法只召回和问话对得上的页。列注释不单独进召回。
3. 用值链接和术语锚点确定表，再投影这些表的字段。
4. 只取这些表之间、置信度在 0 到 1 的关联。

## 页面状态

- compiled：编译器可改写。
- confirmed：外键、过线关联，或已接受的问法。无新证据不降级。
- pinned：人不允许编译器覆盖。冲突另开 contradiction 页。
- rejected：墓碑。同一 evidence_class 不能把该主张写回来。
